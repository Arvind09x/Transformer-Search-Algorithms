## 0. Framing

Prior work: Salemohamed, Charlin, Garg, Sharan, Valiant, "Discovering Data Structures: Nearest Neighbor Search and Beyond" (arXiv 2411.03253) shows that a learned 1D search policy is interpolation-like on uniform data and bisection-like on data where the value carries no positional information. Their substrate: an 8-layer transformer learns to sort; the search policy is M separate 3-layer MLPs (one per lookup, M fixed), trained end-to-end with soft Gumbel-softmax lookups. Phases A–C replicate the result with a single autoregressive transformer, hard queries, variable N, environment-decided episode length, and policy-gradient training. They are the baseline, not the contribution.

Contributions:
1. Objective lever (Phase D): under a verified search-cost trade-off, does changing the training objective (mean vs tail) alter the query strategy of an already competent policy?
2. Mechanistic identification (Phase E): identify components causally involved in bracket tracking and value-dependent query selection, and test whether their contributions change under the objective intervention.

Open extensions (Section 11): phase structure across a family of distributions; training-regime dependence; CVaR from scratch; scale and OOD N.

Randomization is out of scope. Criterion: on the worst-case realized query count, deterministic bisection is already optimal (ceil(log2(N+1)) under `cmp`, Appendix A) and no randomized policy can beat it. On the worst-target expected cost it can be beaten: for N = 2, every deterministic policy has worst-target cost 2 (the episode ends only on a hit), while querying a uniformly random index first gives expected cost 1.5 for either target. Excluding randomization is a scope decision, not an impossibility; it stays with ski rental / marking.

## 1. Environment

- Array: N distinct integers sampled without replacement from [0, V), V = 256, sorted. N per episode uniform on [4, 64] in Phases A–C; fixed in Phase D (Section 8).
- Target T: always present. Under `uniform` and `clustered`, a uniformly random array element. Under `trap`, (N, T) has the same joint law as under `uniform` and the array is built around T (procedure below); given the array, T is not a uniform element.
- Action: one index i in [0, N). Logits for i >= N masked. No feasible-bracket masking: the environment never tracks the bracket for the model.
- Feedback mode (config flag):
  - `cmp`: returns LESS / EQUAL / GREATER, where LESS means A[i] < T (the target lies to the right) and GREATER means A[i] > T. Internal codes 0, 1, 2 = sign(A[i] − T) + 1. The `[T]` token is replaced by the constant `T_MASK` placeholder; the environment compares, the model never sees the target value. Rationale: with distinct integers in [0, V), T itself carries rank information (T = 0 forces rank 1; K−1 | T ~ Hypergeom(255, T, N−1)), so an unmasked `cmp` is not comparison-only.
  - `val`: returns A[i] as a token in [0, V); the model sees `[T]` and compares internally.
- Termination: environment ends the episode when A[i] == T. No EOS token.
- Query cap K(N) = N (`cap_mode = linear`). N distinct queries always find the target, so a policy that never repeats a query and never queries outside the comparison bracket cannot fail; a failure is an execution error by definition, never a slow search. The cap exists only so that an incompetent policy's episode terminates. The logarithmic cap K(N) = 2 * ceil(log2 N) + 2 (`cap_mode = log`, `cap_mult`, `cap_add`) is kept in config for the deadline variant of Section 11.5 and is not the main setting. Repeated queries allowed (that they stop is a finding).
- Cost: C = Q + failure_cost_coef * K(N) * 1[failure], Q = queries used, `failure_cost_coef` = 1 (failure costs 2N, 128 at N = 64). Reward is -1 per query including the successful one, plus the failure penalty on cap. Discount 1.0. Any positive coefficient makes failure strictly worse than every success (which costs at most N), so the cost ordering is fixed; the coefficient's size still scales the failure atom and with it CVaR values, the surrogate weights (R − nu) and the gradient scale, not only the mean penalty. It cannot remove the flat CVaR region that arises when failures fill the selected tail (Section 8), which is why the mean warm-up is retained whatever the coefficient.
- Value distributions. Config: `distribution` in {`uniform`, `adversarial`, `mixture`}; `adversarial` in {`clustered`, `trap`} names the adversarial component; `p` (default 0.10) is used only under `mixture`. Each component is an exact sampling procedure; parameters live in `EnvConfig`:
  - `uniform`: N distinct integers uniformly without replacement from [0, V) (the first N entries of a uniform permutation of [0, V), sorted). Target index uniform on [0, N).
  - `clustered` (parameters `clustered_k`, default 2; `clustered_sigma`, default 8.0): draw k cluster centres c_j i.i.d. uniform on the integers [0, V). Weight every integer x in [0, V) by log w(x) = logsumexp_j [ −(x − c_j)^2 / (2 sigma^2) ], computed in log space. Draw N distinct values by sequential sampling without replacement, each draw proportional to w over the values still available (implemented as Gumbel-top-k: the N largest of log w(x) + Gumbel noise, which has exactly this distribution). Sort. Target index uniform on [0, N). At N = 64, sigma = 8 gives two near-contiguous runs; Phase 0 sweeps sigma (Section 4).
  - `trap` (parameter `trap_strength` s in [0, 1], default 0.75): purpose is a tail case that cannot be detected before the costly decision. Before the first query a `val` policy sees only (N, T), so the requirement is that (N, T) has the same joint law as under `uniform`. Procedure: (1) draw a uniform array A0 and uniform index j0 and keep only T = A0[j0] and j0; (2) the feasible ranks of T are [r_lo, r_hi] with r_lo = max(0, N − V + T), r_hi = min(N − 1, T); (3) the misleading extreme is k_ext = r_hi if T < V/2, else r_lo (a small T suggests a low rank, so the target is placed as high as the array allows, and symmetrically); (4) draw the new rank k' uniformly over the integer ranks between j0 + round(s · (k_ext − j0)) and k_ext inclusive, with round(x) = sign(x) · floor(|x| + 0.5); (5) fill k' values uniformly without replacement from [0, T) and N − 1 − k' values from (T, V); the array is these values plus T, sorted. Properties: s = 0 is the widest window, uniform over [j0, k_ext]; the `uniform` law is not a member of this family (runs without a trap use `distribution = uniform`). s = 1 places T at k_ext exactly, which for T in [N−1, V/2) and [V/2, V−N] is a fixed index given (N, T) and can be pre-empted by a policy with a single probe; hence the default s = 0.75. Under the window, k_ext lies in every window and is the modal rank, with mass E[1 / width], about 0.17 at s = 0.75 and N = 64 (simulated), against 1.0 at s = 1; whether this residual is exploitable is measured by the probe-extreme reference in Phase 0. Below and above T the array is uniform, so the component is detectable only after the first query, through the density jump at T.
  - `adversarial` (distribution setting): every array from the selected component.
  - `mixture` (distribution setting): with probability p an array from the selected component, else `uniform`. Phase 0 selects the component.
- Random-number draw order, so that the same seed reproduces arrays across settings: three generators spawned from the seed, for N, the mixture flags, and the arrays. The array generator draws A0 and j0 for every row first, then the adversarial component for flagged rows. Under `trap` this makes (N, T) identical across `uniform`, `adversarial` and `mixture` for the same seed; under `clustered` only N is shared.
- Reference policies (in `teachers.py` and `dp.py`), all acting only on the observation the model sees (N, T under `val`, and the query/feedback history), never on hidden state:
  - Binary search: floor midpoint (lo + hi) // 2 of the comparison bracket; identical actions under `cmp` and `val`.
  - Interpolation search (`val` only): with the bracket's m unknown elements, L = b − a − 1 integers strictly between the bounding values a and b, and t = T − a, query index lo + round((m − 1)(t − 1) / (L − 1)), with index lo when m = 1 and round(x) = floor(x + 1/2). This is the posterior-mean rank of T under the `uniform` law (k − 1 ~ Hypergeom(L − 1, t − 1, m − 1), Appendix A); it maps t = 1 to lo and t = L to hi, is exact on a dense bracket (L = m), and always lies inside the value-feasible range. It differs from the classical a-to-b linear formula by well under one index. It remains a one-step heuristic, not the Bayes action.
  - Interpolate-once-then-bisect (`val` only): interpolation at the first query, binary search afterwards.
  - Value-feasible midpoint (`val` only): floor midpoint (vlo + vhi) // 2 of the value-feasible range [vlo, vhi] defined below. Differs from binary search exactly when the value constraints narrow the comparison bracket; the comparison bracket is a strawman for a `val` policy's tail, this is the fair bisection-class reference under `val`.
  - Guarded interpolation (`val` only; parameter `guard_frac` g, default 0.25): the interpolation query clamped to [vlo + floor(g * w), vhi - floor(g * w)] with w = vhi - vlo + 1 the width of the value-feasible range; for g < 1/2 the clamped interval is never empty, and for w < 1/g (w <= 3 at g = 0.25) the clamp is inactive. Each query therefore eliminates at least floor(g * w) + 1 candidates on either outcome; the point is to bound the tail of interpolation without giving up its mean on uniform data.
  - Interpolate-k-then-value-feasible-midpoint (`val` only; parameter k in `interp_k_grid`, default {1, 2}): interpolation for the first k queries, value-feasible midpoint afterwards. k = 1 with the comparison midpoint as the continuation is the interpolate-once policy above; both continuations are reported so that the two are separable.
  - Adaptive switch (`val` only; parameter `switch_threshold` theta, default 0.5): interpolation while every query so far has eliminated at least a theta fraction of the value-feasible range it was taken in; the first query that eliminates less than theta switches the policy permanently to the value-feasible midpoint. One concrete member of the adaptive family the review asks for; the family itself (switching on a posterior over components, or a learned switching rule) is not enumerated, and a mixture-aware DP or Monte Carlo over these candidates stands in for it.
  The guard fraction, k grid and switching threshold are Phase 0 settings (`phase0` config). None of these is the Bayes action on any distribution; they are strong hand-designed references, and the Phase 0 statement is about them (Section 4).
  - Probe-extreme (`val` only; Phase 0 sanity reference for `trap`): first query at k_ext(N, T) as defined by the trap construction, then either binary search (`bisect` variant, bounds the exploit's tail) or interpolation (`interpolate` variant, bounds its mean). Phase 0 reports both.
  - Exact discrete DP (Appendix A) for `cmp` and for `val` under `uniform` (`dp.py`).
  - Mixture one-step DP (`val` only; `trap` and `uniform`/`trap` mixtures; `posterior.py`): at each state compute the exact posterior over the rank of T from (N, T, lo, hi, a, b) under the configured mixture (Appendix A, other distributions), and query the bracket position j minimizing 1 + sum over outcomes of P(outcome | posterior) * C_uniform(next state), i.e. one exact mixture-aware step with the uniform DP table as the continuation value. It is not the mixture optimum (the continuation ignores the mixture); it is the strongest cheap distribution-aware reference. "Distribution-aware DP/MC reference" in Section 4 means this policy plus Monte Carlo evaluation of every candidate on the condition's arrays. Under `clustered` there is no such reduction and the Monte Carlo over candidates is the only reference.
- Brackets, as computed by policies and metrics from the history (the environment tracks none of this): the comparison bracket [lo, hi] is the inclusive index range consistent with the comparison outcomes, lo − 1 being the largest index answered LESS and hi + 1 the smallest answered GREATER, with sentinels index −1 (value a = −1) and index N (value b = V). Under `val` the value-feasible range [vlo, vhi] = [max(lo, i_R − (b − T)), min(hi, i_L + (T − a))], with i_L = lo − 1 and i_R = hi + 1, is the subset of the comparison bracket where the target can lie given that the values are distinct integers; it can be strictly narrower. The observed bounding values are a = A[lo − 1] and b = A[hi + 1] (sentinels at the array boundaries); A[lo] and A[hi] themselves are unqueried and unknown to the policy whenever lo < hi. The relative target position is rho = (T − a) / (b − a) in (0, 1), and the posterior-mean rank under the `uniform` law is the interpolation target defined above; Sections 9 and 10 use these two statistics. "Feasible bracket" in Section 9 means the comparison bracket; the value-feasible range is reported in addition under `val`.
- Metrics module is separate from the environment and reward code. Nothing in Section 9 enters the reward.

## 2. Tokenization and model

- Sequence: `[N] [T or T_MASK] q1 f1 q2 f2 ...`. Single token per number; separate token types for sizes, indices, values, comparison feedback. T uses the value tokens (the same embedding as `val` feedback, so T − A[i] is a comparison within one numeric space; position 1 fixes its role). `T_MASK` is a dedicated token for the `cmp` placeholder; `PAD` is used only for right-padding after the episode, which no decision position attends to under the causal mask. Vocabulary fixed from the architecture constants, not the run (sizes 1..n_index_logits, values 0..V−1, indices 0..n_index_logits−1, three comparison codes, `T_MASK`, `PAD`), so every run and checkpoint shares token ids and embedding shapes (C1 → C2 continuation, cross-checkpoint probes and patching). The final feedback token of a finished episode is encoded even though no decision reads it, for exact decode and complete Phase E traces. Context length 130 (2 + 2 * K(64) = 130 under K(N) = N; 32 suffices for the log-cap variant of Section 11.5).
- Decision position t: the sequence position whose output logits produce q_t, i.e. the position of f_{t−1} (of `[T or T_MASK]` for t = 1). It precedes the q_t token, so nothing computed there has seen the chosen action. Loss / reward are applied at decision positions only; probes and patching (Section 10) read the residual stream at decision positions, never at the q_t token. Output head: 64 index logits, masked at >= N.
- Decoder-only causal transformer: 4 layers, d_model 128, 4 heads (32 per head), d_ff 512, GELU, pre-LayerNorm, learned positional embeddings, dropout 0. Approx 0.86M parameters; exact count recorded from the implementation. Same architecture in every phase.
- Single-token numbers throughout v1. Digit encoding is a separate tokenization for an OOD-N study (Section 11.4), not a fallback for bracket-tracking failure.

## 3. Training configuration (v1 defaults, recorded verbatim in `config.py`)

Config is a top-level dataclass composed of section sub-dataclasses (env, model, optim, rl, cvar, budget, eval, phase0), serialized to JSON in each run directory.

Optimization:
- AdamW, betas (0.9, 0.999), eps 1e-8, weight decay 0, global grad-norm clip 1.0, constant learning rate.
- Imitation lr 3e-4; RL lr 1e-4. If RL fails to learn, one sweep over {3e-5, 1e-4, 3e-4} during the pilot, then freeze.
- Imitation / pilot batch 256 episodes; main RL batch 1,000 episodes (matched across mean and CVaR).
- Imitation budget: cap 10,000 updates x 256 episodes; validate every 250 updates; early stop when closed-loop mean query count on the validation set is within +0.5 of the teacher's mean on the same arrays for 3 consecutive validations.
- Gradient aggregation: sum within episode, average across episodes.

RL estimator (Phases B, C, and Phase D mean branch):
- REINFORCE with reward-to-go.
- Baseline: lagged moving average indexed by (N, decision step); update after each batch as 0.95 old + 0.05 new.
- Entropy coefficient 0.01, held for the first 80% of updates, linearly reduced to 0 over the final 20%. In Phase D the schedule is restarted at branching over the Phase D update budget and applied identically to both branches (the CVaR branch's surrogate gets the same entropy term, same coefficient, same schedule); the entropy term is part of the objective while active and is reported as such. Entropy 0 in both branches is the ablation.
- Curriculum off by default: train directly on N ~ Uniform{4..64}. Fallback 4–8 -> 4–16 -> 4–32 -> 4–64 only if direct training consistently stalls with predominantly capped failures, after checking implementation and learning rate. Retain and report the direct-training baseline; apply the same curriculum protocol to every compared condition if used.

CVaR (Phase D):
- alpha = 0.10 initially (100 tail episodes per 1,000-episode batch); follow-up 0.05 and 0.25.
- Estimated over the entire batch with quantile/tie handling (Appendix B), by `cvar.py`, the single implementation shared with evaluation; no microbatching.
- Initial mixture probability p = 0.10, subject to Phase 0 validation.
- Batch-maximum objective deferred.
- Diagnostics logged every update (Section 8): the empirical quantile nu, the number of episodes strictly worse than nu (the only ones with nonzero weight in the surrogate), the fraction of batches with all-zero CVaR weights, failure mass, and the CVaR-gradient norm relative to the entropy-gradient norm.
- Mean-CVaR blend: `cvar.mean_weight` in [0, 1), default 0 (pure CVaR). If a nonzero value is ever used to escape a flat region, the branch objective is (1 − w) CVaR + w mean and is reported as that objective, not as CVaR.

Budgets (provisional caps, validated against pilot curves before the grid):
- Pilot: 1,000 updates x 256 episodes, 2 seeds.
- Main RL: 5,000 updates x 1,000 episodes = 5M episodes per run, >= 5 seeds. Not derived from any tokens-per-parameter rule. With autoregressive sampling of up to K(64) = 64 steps this is at most 3.2e8 individual action evaluations per run, but a batched rollout runs until the longest episode in the batch ends, so the real cost is set by the per-batch maximum: 5-10 steps for a competent policy on `uniform`, longer on tail-heavy conditions, and the full 64 early in RL when most episodes fail. Batched 1,000 episodes per step this is on the order of 1e5 network calls per run; runtime depends on the batching and the episode-length distribution, not on the evaluation count. CPU expected to suffice for the pilot and Phases A/B; GPU expected for C2 warm-ups and Phase D (5 C2 runs + 10 branch runs). The budget is set only after the compute pilot (Section 14 step 2): DP runtime on increasing (N, V), episodes per second of rollout, seconds per training update at batch 256 and 1,000, and peak memory, on the hardware that will run Phases C-D. One documented budget decision after that pilot, applied identically to compared conditions.
- Validation set 2,000 episodes per condition; final test 10,000 episodes per condition per seed (500 episodes in a 5% tail). Generated from fixed data seeds held in config (val_data_seed = 1000, test_data_seed = 2000), identical across all runs; the training seed is per run. Validation every 100 pilot updates / 250 main updates; checkpoint at every validation. Validation and test arrays kept separate.
- Evaluation: greedy and sampled actions, both reported. Variable-N results reported by N.

## 4. Phase 0: reference-policy pilot (no neural training)

- Candidates: `uniform`; `adversarial` with each component; `mixture` with each component over p in {0.02, 0.05, 0.10, 0.25}. For `clustered`, sigma in {8, 16, 32}. At fixed N in {32, 64}, simulate 2e5 episodes per reference policy from sim_seed = 3000, and validate the frozen condition on fresh arrays from fresh_seed = 3001 (both disjoint from the validation/test seeds; settings held in config as phase0): bisection, value-feasible midpoint, interpolation, guarded interpolation (g in {0.25}; {0.125, 0.375} if the trade-off is marginal), interpolate-k-then-value-feasible-midpoint for k in {1, 2}, interpolate-once-then-bisect, adaptive switch (theta = 0.5), the uniform DP, and on `trap` conditions the mixture one-step DP (Section 1); every candidate is evaluated by Monte Carlo on the same arrays. The strong value-aware policies are in the set so that the trade-off is between the best mean policy and the best tail policy among strong candidates, not between interpolation and a value-blind bisection. Sanity reference for `trap`: probe-extreme (Section 1), first query at the trap's modal rank k_ext(N, T), in both the `bisect` and `interpolate` continuations, included so that any residual pre-emption exploit of the trap is measured rather than assumed absent.
- Run under K(N) = N; no reference policy ever reaches it. Report mean cost, CVaR_alpha for alpha in {0.05, 0.1, 0.25} (Appendix B), full cost histograms, and for information the fraction of episodes per policy that would have exceeded the logarithmic cap (how much the Section 11.5 deadline would truncate).
- Decision rule: Phase D proceeds only on a distribution with a reproducible mean-tail trade-off among strong reference policies: the policy with the best mean does not have the best CVaR at some alpha, and the CVaR gap between them exceeds its Monte Carlo uncertainty (bootstrap over the 2e5 episodes) and reproduces on the fresh_seed arrays. Choose and freeze (distribution, p, alpha, N); report the condition as pilot-selected, with the reference gap G_ref = CVaR(best-mean policy) − CVaR(best-tail policy) and the corresponding mean gap recorded; G_ref is the scale against which Phase D effects and the Section 8 competence gate are read.
- What the pilot does and does not establish: it estimates the reference gap and its sampling uncertainty. It cannot establish that a neural branch difference will be detectable across five training seeds, since the variance across seeds is a property of the training runs, not of the reference policies. A crossing between selected heuristics also does not show that no more adaptive policy improves both objectives (Appendix A); the main claims keep that qualification.
- If no candidate shows the trade-off, redesign the adversarial component (trap construction, including `trap_strength`) before any RL.

## 5. Phase A: imitation (pipeline validation)

- Teacher-forced CE on binary-search demonstrations, `cmp` feedback (T masked), N in [4, 64].
- Evaluate closed-loop only on the fixed validation set.
- Success: mean closed-loop query count within +0.5 of the binary-search teacher's own mean on the same arrays (at N = 64 the teacher averages 5.125, not log2 N = 6).
- Diagnose failures from traces: misreading feedback, losing the bracket, wrong midpoint.
- Consistency check: second imitation model on DP-optimal labels under `cmp`. Compare cost/regret, not actions: optimal comparison trees are not unique (bracket of size 5: positions 2, 3, 4 all give 2.2).

## 6. Phase B: RL discovery, `cmp` feedback

- Fresh initialization, same architecture, Section 3 estimator.
- No shaping of any kind.
- Baseline and reward-to-go preserve the expected gradient; entropy changes the objective while active; curriculum (if used) changes the training distribution and path. None change the final objective's optimum, but with multiple optimal policies the path can decide which is reached. Removing them is an ablation.
- Expected outcome: cost matching the `cmp` DP (bisection-class). If not, the fault is the estimator or architecture; Phase A is the diagnostic.

## 7. Phase C: RL discovery, `val` feedback (replication, then warm-ups)

Two stages with different training distributions; v1.5 conflated them.

| Stage | Distribution | N | Purpose |
|---|---|---|---|
| C1 | `uniform` | variable, [4, 64] | replication of the Salemohamed et al. result in this substrate |
| C2 | frozen Phase 0 condition | fixed, 64 | competent `mean`-trained warm-ups at the Phase D condition |
| D | same as C2 | same as C2 | objective intervention on the C2 checkpoints |

C1:
- Same as B with raw-value feedback and `[T]` visible.
- Supervised references trained first, same architecture:
  - Binary-search imitation under `val`.
  - DPT-style control: CE on the exact discrete DP-optimal query (Appendix A), trained on diverse valid histories including off-teacher trajectories (DAgger-style coverage), ties among optimal actions handled explicitly. Evaluated closed-loop.
  - These are diagnostics, not impossibility proofs.
- Expected (from Salemohamed et al.): value-dependent first query, mean cost below the binary-search teacher's mean.
- Open question C answers: full interpolation at every step, interpolate-once-then-bisect, or something else? Decided by Section 9 metrics, examined in Phase E.
- Output of C1: the replication statement (Section 9 metrics on `uniform`, variable N) and one checkpoint per seed.

C2:
- Per seed, initialize from the C1 checkpoint of the same seed and continue `mean` RL (Section 3 estimator, same architecture) on the frozen Phase 0 condition at fixed N = 64 until the Section 8 competence gate is met or the C2 budget is exhausted. Continuation rather than fresh initialization is the pick because it is cheaper and keeps one lineage per seed; fresh initialization at the Phase D condition is the fallback if continuation does not reach the gate, and is then applied to every seed. Whichever is used is reported.
- C2 also has a replication reading: how the `uniform`-trained strategy adapts when the distribution changes to the mixture, under the mean objective alone. This is recorded, but it is not the Phase D question.
- Output of C2: one competent `mean`-trained checkpoint per seed (>= 5) at the Phase D condition, with its competence-gate report. These are the Phase D warm-ups. Branching from C1 checkpoints directly (both branches adapting to the mixture while the objective differs) would still be a controlled experiment, but it answers a question about objectives during distribution shift, not about changing the objective of an already competent policy, which is the stated question.

## 8. Phase D: objective lever (contribution 1)

Design: warm-up then matched branches, per seed.
- For each seed s in 1..5: take the C2 checkpoint for seed s; copy weights and optimizer state identically into Branch 1 (`mean`) and Branch 2 (`cvar(alpha)`); continue both with the same data stream, step budget, batch size (1,000), entropy schedule (Section 3).
- Same data stream means the same arrays and targets per update, nothing more. Environment generation uses its own `numpy.random.Generator` seeded identically in both branches; action sampling uses a separate generator. Trajectories differ by construction (different policies, different episode lengths), so any shared generator would desynchronize the arrays after the first update. Per-seed warm-ups (not one shared checkpoint) so that warm-up variability is in the comparison and the branches do not share a single lineage.
- Fixed N = 64 (N = 32 for debugging). With variable N the CVaR tail is simply the largest arrays and CVaR training reallocates effort across N rather than changing strategy. Variable N returns afterwards, stratified by N.
- Warm-up rationale: a fresh policy fails a large fraction of episodes (a uniformly random policy with repeats fails 1 − (1 − 1/64)^64, about 37%, at N = 64), all failures share the cap cost, the tail is a block of identical costs, the advantage is zero, CVaR has no gradient. Batch size does not fix this, and neither does the failure coefficient (Section 1).
- Competence gate (checked on the C2 checkpoint, on the validation set, greedy and sampled; thresholds provisional, Section 16): `failure rate < alpha` is necessary but far too weak. At N = 64 the failure cost is 128, so if 0.5% of episodes fail and the rest of the worst decile costs 6, CVaR_0.10 = (0.005 * 128 + 0.095 * 6) / 0.10 = 12.1, and removing the failures alone lowers it to 6, a gain of 6.1 with no change in search strategy, larger than any plausible reference gap. Under K(N) = N a failure can only come from repeated or out-of-bracket queries, so the gate bounds execution errors directly, relative to the reference gap G_ref from Phase 0:
  (i) failure rate < alpha / 100 in both greedy and sampled evaluation (strict because under K(N) = N a competent policy has no legitimate failures);
  (ii) repeated-query rate and out-of-value-feasible-range query rate each < 1% of queries;
  (iii) execution-error CVaR share: recompute CVaR_alpha with every episode that failed, repeated a query, or queried outside the value-feasible range assigned the cost of the value-feasible-midpoint policy on the same array; the difference from the actual CVaR must be < 0.25 * G_ref;
  (iv) sampled-minus-greedy CVaR gap < 0.25 * G_ref, so that action randomness is not the dominant tail term.
  A checkpoint failing the gate continues C2 training (then the learning-rate sweep, then fresh initialization at the Phase D condition, Section 7); Phase D does not branch from it.
- Decomposition of a branch difference (Section 9 metrics, both branches, same test arrays): any CVaR or mean difference is attributed, in order, to (a) fewer execution mistakes (failures, repeats, out-of-range queries), (b) lower action randomness (sampled vs greedy), (c) a different first query (a function of (N, T) only), (d) different later queries on matched valid histories, (e) a different response to evidence of a trap (the first observation whose value is inconsistent with the uniform posterior, Section 9). A changed action on the same valid history, (d) and (e), is the evidence for a changed decision rule; a lower aggregate CVaR alone is not.
- CVaR flat regions beyond the failure plateau. Example without failures: P(C = 3) = 0.7, P(C = 6) = 0.3 gives CVaR_0.1 = 6, and moving the cost-6 mass from 0.3 to 0.2 leaves CVaR_0.1 = 6. In the surrogate, episodes with R = nu carry weight zero, so "100 tail episodes per batch" is an upper bound on the number of episodes with nonzero weight; when the quantile atom covers the whole tail the gradient is exactly zero. Larger batches reduce sampling noise; they cannot remove a flat region of the population objective, and lowering the failure coefficient only rescales the failure atom without moving probability mass out of the tail. The Section 3 diagnostics (quantile, strictly-worse count, zero-weight batch fraction, failure mass, CVaR-to-entropy gradient ratio) are logged every update and reported for both branches, and a run whose zero-weight fraction is high is read as "no usable learning signal", not as "no effect of the objective".

Objectives, all on return R = -C:
- `mean`: E[R].
- `cvar(alpha)`: variational definition (Appendix B). Per batch of B: nu = empirical alpha-quantile of R; ascent surrogate = (1 / (alpha B)) * sum over episodes with R <= nu of (R - nu) * sum_t log pi(a_t); negate for a minimized loss; stop gradients through R and nu; normalize by alpha B, not by the count of tied episodes.
- `max`: deferred.

Predictions are conditional on Phase 0: in the frozen condition the best-mean reference (interpolation-class) has worse CVaR than bisection-class or the hybrid. Prediction: Branch 1 stays interpolation-class; Branch 2 moves toward bisection or interpolate-once-then-bisect (worst case 1 + ceil(log2 N), not binary search's exact bound). Hybrid outcome is plausible; Phase E distinguishes it.

Reporting: per branch and seed, mean cost, CVaR_alpha with fractional boundary mass, failure rate and failure cost separately, greedy and sampled evaluation, per-step metrics (Section 9), with reference-policy values on the same test set. The primary statistic is the paired within-seed branch difference (Branch 2 − Branch 1 on the same test arrays), reported per seed and as mean and spread over seeds, next to G_ref. Five seeds are the starting budget, not a power guarantee; if the paired differences are of inconsistent sign, more seeds, not a stronger claim.

What counts as a result. The strongest outcome connects three levels: performance (a reproducible mean-tail shift between branches), behaviour (on matched histories the query-selection rule changes in a way that accounts for the shift, Section 9), and mechanism (targeted interventions disrupt or reproduce that behavioural change, Section 10). A specific form it might take: mean training keeps aggressive value-based guesses; tail training keeps the value-feasibility computation but moves toward balanced splitting when the observed values are inconsistent with the uniform posterior. A null result is informative only if all of the following are shown: G_ref is substantial; the warm-ups passed the competence gate; the CVaR updates had a usable signal (diagnostics above); the branches received enough updates to move (the mean branch's own drift is the yardstick); and the Section 9 measurements can detect the hypothesized change (they separate the reference policies on the same arrays). Otherwise "no difference" means the optimization stalled.

## 9. Metrics (defined before training)

Per condition, >= 5 seeds, fixed held-out arrays:
- Success rate within cap; failures reported separately with their cost.
- Query count on successes vs the binary-search teacher's mean and the DP reference on the same arrays; per-step regret Q(s, a) − V(s) against the uncapped DP table (Appendix A). Certification: with m the comparison-bracket size and r = K(N) − q the queries remaining, V(s) is the environment's exact optimum when m <= r, and Q(s, a) is exact when in addition every successor reachable under a satisfies m' <= r − 1 (automatic for a distinct in-bracket query, since m' <= m − 1; for a repeat or out-of-bracket query it requires m <= r − 1, and on the last available query the true cost is 1 plus the failure penalty, not 1 + V(s)). Regret is reported as certified exact only when both hold; other states, which arise only after repeated or out-of-bracket queries, are reported as not certified exact and counted separately. The same certification applies to DP teacher labels on DAgger histories (Section 7).
- Fraction of queries inside the current feasible bracket (the comparison bracket, Section 1, so the metric is the same object under `cmp` and `val`); repeated-query rate. Under `val`, additionally the fraction inside the value-feasible range, so that losing the bracket and ignoring value constraints are scored as different errors (binary search tracks the bracket and ignores values by design).
- Sensitivity to observations that no longer constrain the bracket (descriptive, not a correctness criterion): hold (lo, hi, a, b, T) fixed and perturb an earlier observation that is consistent with them; record whether the action changes. Under `uniform` the state (m, L, t) is sufficient (Appendix A), and under `trap` and any `uniform`/`trap` mixture the 6-tuple (N, T, lo, hi, a, b) is sufficient: both components are uniform given the rank of T, so the history enters the posterior over the rank only through the nearest observed bounds (Appendix A). In all of these, insensitivity to older observations is the correct behaviour and the metric is scored. Under `clustered`, which is not uniform given rank, older (index, value) pairs carry density evidence and sensitivity can be correct; there the metric is reported and compared with the mixture-aware reference, not scored. (v1.7 exempted every mixture; that was wrong for `trap`.)
- Execution-error rates for the Section 8 decomposition: failure rate, repeated-query rate, out-of-value-feasible-range rate, and the sampled-minus-greedy gap in mean and CVaR.
- Trap-evidence response (`val`, mixture conditions): the first step at which the observed values are inconsistent with the `uniform` posterior at a stated level (the observed (index, value) pair has probability below 0.01 under the Hypergeometric posterior of Appendix A); the policy's next action relative to the interpolation and value-feasible-midpoint actions from that state. Compared between branches on matched histories.
- Fraction of the feasible bracket (comparison bracket) eliminated per query, by step index; under `val`, the same for the value-feasible range.
- Order-preserving relabelling test (`val` only): counterfactual with the same ranks but fresh distinct values (same N, same target rank, values resampled and assigned by rank). Evaluate on matched histories (same query indices and comparison outcomes replayed); compare the next query and the change in the index logit vector. A changed query = sensitivity to numeric encoding; an unchanged query is not proof of comparison-only computation.
- Disagreement-state tests: on states where the value-feasible midpoint and interpolation predict different queries, does the policy move in interpolation's direction? Does changing the observed bounding values a = A[lo − 1], b = A[hi + 1] (indices fixed, T fixed, history still consistent with a valid sorted array) change the action?
- Distance to reference policies: per-step agreement with binary, value-feasible midpoint, interpolation, guarded interpolation, interpolate-k, adaptive switch, DP-optimal. Decision-position convention (Section 2): q_t is predicted from, and compared with references on, the history preceding q_t.
Exact match to any single teacher is not a metric.

## 10. Phase E: mechanistic identification (contribution 2)

Run on Phase C checkpoints and both Phase D branches. Deliverable: identify components causally involved in (a) bracket tracking and (b) value-dependent query selection, and test whether their contributions change between the `mean` and `cvar` branches.

1. Behavioural discriminators from Section 9, per step.
2. Probes (diagnostic only). The search model is frozen; only probe parameters train; no probe loss ever enters the search model's training (that would teach the representation rather than inspect it).
   - Labels: lo and hi (64-way classification over indices) first; under `val`, the observed bounds a = A[lo − 1] and b = A[hi + 1] (256-way, with the sentinels mapped to two extra classes) and the relative position rho = (T − a) / (b − a) (regression) once the endpoint probes behave sensibly. v1.5 named A[lo] and A[hi]; those are unqueried values inside the bracket, unknown to the policy, and predicting them would be a posterior-prediction experiment, a different measurement from maintaining observed bounds, kept out of the main probe set. Labels are computed from the history by `teachers.bracket` and `teachers.value_bounds`, never annotated.
   - Probe class, fixed in advance: linear (`Linear(d_model, classes)`, softmax, cross-entropy) is the primary; a one-hidden-layer MLP (d_model -> 64 -> classes, ReLU) is the secondary diagnostic. Probe size is never increased to reach a score; the linear/MLP gap is itself reported.
   - Read site: residual stream at the decision position (Section 2), at the embedding output (layer 0) and after each of the 4 blocks, same convention at every layer; separate probes per layer, identical data and procedure.
   - Dataset: valid histories replayed through the frozen model (no activations are stored during training; checkpoints and seeds are, and the probing set is extracted afterwards). The set must include off-policy histories (uniformly random valid queries, as the test history generator already produces, and perturbed-teacher histories), not only the model's own trajectories: under a bisection-like policy the bracket after t steps is close to a deterministic function of (N, t, last query, last feedback), so a probe trained on on-policy trajectories alone can recover lo and hi from the step index and the last token without reading any bracket representation. Split by whole episode, all prefixes and counterfactual variants of an episode in one partition.
   - Reporting: top-1 accuracy and mean absolute index error, stratified by decision step and by N, and separately for states where the probed endpoint was established two or more queries earlier (the latest (query, feedback) pair pins at most one endpoint). The pre-query state (lo = 0, hi = N − 1) is excluded from headline numbers.
   - Baselines, all three required before any probe result is reported: (i) the same probe given only the last (query, feedback) pair, (ii) the same probe on a randomly initialised model of the same architecture at the same layer, (iii) the layer-0 probe. The claim a probe can support is "recoverable from this layer's representation by this readout class, beyond what the last observation and the input structure give"; nothing about use.
   - Branch comparison (Phase D): the same valid histories replayed through both frozen branches, equivalent probes, same protocol; a change in probe accuracy is a change in accessibility to that readout, not evidence that information disappeared.
   - Pipeline check: the first probes are fitted on one Phase A checkpoint (Section 14 step 4) to exercise extraction, labels, split and baselines; that model imitated a teacher, so its probe results are a diagnostic of the pipeline, not a finding.
   Decodability is neither necessary nor sufficient for use (Hewitt and Liang 2019; Ravichander et al. 2021); the patching below is what tests use.
3. Activation patching with matched clean/source pairs of identical length and token layout, differing only in the bracket (indices) or only in the bounding values a, b with T fixed. Every counterfactual history must be consistent with some valid sorted array of distinct integers in [0, V) (checked by construction, not assumed); histories that no array could produce are off-distribution and are not used. Disruption and restoration directions; separate pair sets for locating components and for confirming their effect, so that the confirmation is not on the pairs that selected the components; metric = normalized logit difference toward the source query, reported together with the behavioural change (does the argmax action move, and to where); pairs whose clean-minus-source logit difference is below a stated floor (0.5 nats) are excluded from the normalized metric rather than divided by a near-zero denominator; >= 50 pairs per condition in each set. A heat map locates relevant information; it does not identify the operation.
4. Circuit-level validation: ablate and re-patch the located heads/MLP neurons, verify the behavioural effect, compare the component set and effect sizes between branches. Within a matched branch pair the shared C2 initialization makes head-by-head comparison meaningful. Across seeds it does not: head (layer, index) numbers are arbitrary across independently trained models, so cross-seed comparison is functional (same behavioural effect of ablating the located set, same patching signature), never by component number.
Mechanisms kept open: lookup-like mappings over the finite domain (4096 bracket states under `cmp`), distributed representations, mixed comparison and value-sensitive heuristics, different computations at different steps.
Optional: Tracr-compiled binary search as a reference for attention structure; a comparison aid, not a validation criterion.

## 11. Open extensions

11.1 Phase structure across distributions: one-parameter family; interpolation index vs parameter; compare with DP; sharp transition or smooth blend.
11.2 Training-regime dependence: REINFORCE hard queries vs Gumbel-softmax soft lookups vs CE on DP-optimal; one comparison on `uniform` x `mean`.
11.3 CVaR from scratch: can the tail objective bootstrap a policy given the identical-failure plateau.
11.4 Scale and OOD N: width/depth sweep on cells where a flip occurred; digit tokenization for OOD N; Pythia fine-tuning as the far end of the scale axis. Larger N also needs an action representation beyond the fixed 64-logit head (`model.n_index_logits`, Section 2; a larger head, digit-wise index emission, or a relative action over the bracket) and a longer context than 32; these are separate design decisions, not a tokenization change.
11.5 Search under a deadline: the logarithmic cap K(N) = 2 * ceil(log2 N) + 2 (`cap_mode = log`, context 32) as a separate experiment. Under it a slow search becomes a failure, the mean objective itself contains a deadline incentive, and exact references need a remaining-queries dimension in the DP state (about 14x the uniform table, one table per distinct K(N)); none of this is built for the main line.

## Appendix A. Exact discrete DP reference

Environment samples N distinct integers without replacement from [0, V). Continuous order-statistic approximations (Binomial/Beta) are not exact here (sampling fraction 25% at N = 64, V = 256) and are retained only as a sanity check.

Cap. The recurrences below have no cap. Under K(N) = N none is needed: every in-bracket query removes at least one candidate, so the DP policy finishes within m queries from any state it reaches, and from any state with m <= r remaining queries the capped optimum equals the uncapped value (a capped policy's expected cost is at least the uncapped optimum, which the uncapped policy attains within budget). States with m > r arise only after repeated or out-of-bracket queries; there the table is an approximation, and Section 9 states the certification conditions for V, Q and the resulting regret. Under the log cap (Section 11.5) exactness would need a remaining-queries dimension in the state; not built.

`cmp` (T masked): state m = bracket size; target uniform over it. C(m) = 1 + min_j [ (j-1)/m * C(j-1) + (m-j)/m * C(m-j) ], C(0) = 0, C(1) = 1. Optimal j is not unique in general; record the optimal set. Worst-case variant W(m) = 1 + min_j max(W(j-1), W(m-j)) = ceil(log2(m+1)). The uniform-rank assumption holds under `uniform` and `clustered`; under `trap` the rank of T is concentrated near an extreme, so this DP is not the optimum on `trap` rows and `cmp` results on mixtures containing `trap` are reported against it as a reference only.

`val`, `uniform`: state (m, L, t) with m = unknown array elements in the bracket, L = b - a - 1 = integers strictly between the bounding values a and b, t = T - a = position of T among them (1-based). Initial state (N, V, T + 1), from the sentinels a = −1 at index −1 and b = V at index N (Section 1); `teachers.py` and `dp.py` use the same sentinels. Posterior over rank k of T in the bracket: k - 1 ~ Hypergeom(population L - 1, successes t - 1, draws m - 1). Querying bracket position j: found w.p. P(k = j); A[j] < T w.p. P(k > j), and conditional on k the value A[j] is the j-th smallest of k - 1 integers drawn without replacement from the t - 1 integers below T, giving an exact discrete distribution over the new (m - j, L', t'); symmetric for A[j] > T. C(m, L, t) = 1 + min_j [ P(k > j) E[C(next)] + P(k < j) E[C(next)] ]. State count: sum over m in [1, 64] and L in [m, 256] of L values of t = 2,061,664 (about 2.06M) before feasibility pruning. The cost is not the state count: each state evaluates up to m actions, and each action's transition sums over up to L possible observed values, so a direct recurrence has on the order of 1e9-1e10 transition terms. It is memoized and vectorized over t for fixed (m, L), and its runtime is measured on increasing (N, V) in the compute pilot (Section 14 step 2) before the full table is attempted; if the full table is too slow, the fallback is exact DP for the comparison bracket with Monte Carlo over values, and the plan says so where the DP reference is used. Validate by exhaustive enumeration at e.g. N <= 5, V <= 12. Interpolation search is a one-step heuristic approximation; the DP is the Bayes optimum for this exact sampling model.

Other distributions. Under `trap` and any `uniform`/`trap` mixture the posterior over the rank k of T is exact and cheap: both components are uniform given the rank, so with observed bounds a at index lo − 1 and b at index hi + 1, Lik(history | k) is proportional to C(T − 1 − a, k − lo) / C(T, k) times C(b − T − 1, hi − k) / C(V − T − 1, N − 1 − k), and posterior(k) is proportional to pi(k | N, T) · Lik(history | k) for k in [lo, hi], with pi = (1 − p) · Hypergeom + p · (trap window law, pi_trap(k | N, T) = sum over j0 of P_uniform(j0 | N, T) · 1[k in window(j0)] / |window(j0)|). The sufficient statistic is (N, T, lo, hi, a, b); under `uniform` the hypergeometric prior collapses it to (m, L, t), under the mixture it does not. A full DP over the 6-tuple is about 1e11 transition terms per (N, T) at N = 64 and is not built; the O(m) posterior supports exact one-step Bayes quantities (hit probability per position, the exact outcome distribution of any query), hence the mixture one-step DP reference of Section 1 (`posterior.py`), and exact per-step evaluation of any candidate. `clustered` is not uniform given rank and has no such reduction. Otherwise use a Monte Carlo reference over candidate policies. CVaR is not Bellman-decomposable; use augmented-state DP (Bauerle and Ott 2011) or compare candidate policies' simulated cost distributions. Comparing candidates establishes which candidate wins, not the global CVaR optimum; a mean-tail crossing between selected heuristics does not show that no more adaptive policy improves both. The main text keeps this qualification wherever the Phase 0 trade-off is cited.

## Appendix B. CVaR

For cost C and level alpha, CVaR_alpha(C) = min_nu [ nu + (1/alpha) E[(C - nu)^+] ] (Rockafellar and Uryasev 2000). Authoritative. For discrete costs with atoms at the quantile, E[C | C >= q_alpha] is not equal to CVaR in general; empirical CVaR takes the worst ceil(alpha B) episodes with fractional weight on the boundary atom so that exactly alpha mass is counted. alpha = 1 is the mean; alpha -> 0 is the max.

Gradient support. In the Section 8 surrogate the weight of an episode is (R − nu) 1[R <= nu] / (alpha B); episodes with R = nu have weight zero. With discrete costs the quantile is usually an atom with mass, so the number of episodes with nonzero weight is the count strictly worse than nu, which can be far below ceil(alpha B) and can be zero. The estimator remains the correct CVaR estimate with fractional boundary mass; it is the gradient, not the value, that loses support. Both counts are logged (Section 3). Value, quantile, weights and counts are computed by `cvar.py` for training and evaluation alike.
